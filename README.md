# 박상태 디지털 명함 (statepark62.github.io)

국립공주대학교 물리교육과 박상태 교수의 디지털 명함. 한국어·영어·일본어 3개 언어를 지원하며,
경력·관심사 같은 내용은 구글 스프레드시트에서 관리한다.

- **주소**: https://statepark62.github.io
- **영어판**: https://statepark62.github.io/en.html (→ `index.html?lang=en` 로 안내)
- **일본어판**: https://statepark62.github.io/ja.html (→ `index.html?lang=ja` 로 안내)

---

## 1. 전체 구조 한눈에 보기

```
방문자 브라우저
   │  (페이지를 열면)
   ▼
index.html  ──fetch──▶  content.json   (같은 저장소의 정적 파일, 즉시 응답)
   │
   │  (방명록 전송 · 방문자 수 조회할 때만)
   ▼
Google Apps Script (/exec 주소)  ──▶  스프레드시트 "명함 방명록"
                                         ├─ 1번째 시트: 방명록 메시지 로그
                                         ├─ "이력활동" 탭
                                         └─ "관심사" 탭
                                              │
                                              │ (시트 메뉴 "지금 명함에 반영하기"를 눌렀을 때만)
                                              ▼
                                        GitHub API 로 content.json 을 직접 덮어씀(커밋)
```

**핵심 원칙**: 명함은 평소에 완전한 정적 사이트다. 방문자가 올 때마다 시트를 조회하지 않는다.
내용이 실제로 바뀌는 시점은 **사람이 스프레드시트에서 "반영하기" 버튼을 누른 순간뿐**이다.

## 2. 저장소(statepark62.github.io) 파일 구성

| 파일 | 역할 | 평소에 손댈 일 |
|---|---|---|
| `index.html` | 레이아웃·디자인·모든 기능(계절 배너, 방명록, 방문자 수, 언어 전환)을 담당하는 유일한 템플릿. 3개 언어가 이 파일 하나를 공유한다. | 거의 없음 (디자인을 바꿀 때만) |
| `content.json` | 실제 문구 전부를 한국어·영어·일본어 세 벌로 담은 데이터 파일. | 없음 — 스프레드시트의 "반영하기"가 이 파일을 자동으로 갱신한다 |
| `en.html`, `ja.html` | `index.html?lang=en` / `?lang=ja` 로 넘겨주기만 하는 안내판(리다이렉트). 예전 주소를 즐겨찾기한 사람을 위한 것. | 없음 |
| `manifest.json` | 스마트폰 홈 화면에 "앱처럼" 설치할 때 쓰이는 설정(이름, 색상, 아이콘 목록). | 없음 |
| `icon-512.png`, `icon-192.png`, `apple-touch-icon.png`, `favicon-32.png`, `favicon.ico` | 브라우저 탭 아이콘 및 홈 화면 앱 아이콘 (朴 글자 모양). | 없음 |
| `profile.jpg` | 프로필 사진 예비 파일. 실제로 화면에 쓰이는 사진은 `index.html` 안에 이미지 자체가 내장(Base64)되어 있어, 이 파일은 나중에 사진을 바꿀 때 참고용. | 사진을 바꿀 때만 |

`content.json` 안에서 스프레드시트가 직접 덮어쓰는 부분과, 그대로 유지되는 부분이 나뉜다.

- **시트가 관리하는 부분**: `sections.career.items`(학력·경력), `sections.research.bullets`(연구),
  `sections.teaching.bullets`(강의), `sections.writing.bullets_html`(저술), `sidebar.chips`(관심사 키워드)
- **content.json에만 있고 시트로 관리하지 않는 부분**: 이름·소속·연락처, 소개 문단, 계절 배너 사진,
  연구/강의/저술 섹션의 사진과 캡션, 방명록 안내 문구, 화면 라벨 등 — 자주 바뀌지 않는 것들

## 3. 내용을 업데이트하는 방법 (평소에 하는 일)

1. 스프레드시트 **"명함 방명록"** 을 연다.
2. **"이력활동"** 탭에 학력·경력·연구·강의·저술 항목을 입력한다.
   - 구분: `학력` `경력` `연구` `강의` `저술` 중 하나
   - 학력·경력은 시작·종료를 채운다 (종료를 비우면 "현재"로 자동 표시)
   - 연구·강의·저술은 시작·종료를 비우고 내용만 적는다
   - 영어·일본어 칸은 비워두면 반영할 때 자동 번역되어 채워진다. 번역이 어색하면 그 칸을 직접 고쳐 쓰면 그 값이 우선한다
   - 한국어 칸(내용_한/메모_한)을 나중에 고치면, 같은 줄의 영어·일본어 칸이 자동으로 비워져 다음 반영 때 새로 번역된다
3. **"관심사"** 탭에 키워드를 한 줄에 하나씩 적는다. 강조하고 싶은 키워드는 "강조" 칸에 `Y`.
4. 다 됐으면 스프레드시트 위쪽 메뉴 **📇 디지털 명함 → 지금 명함에 반영하기** 클릭.
5. 약 1분 후 `statepark62.github.io` 새로고침 → 반영 확인.

> 반영하기 전에 결과를 미리 보고 싶다면, 브라우저에서 Apps Script 웹 앱 주소 뒤에
> `?mode=content` 를 붙여 접속하면 지금 시트 내용으로 만들어질 JSON을 미리 볼 수 있다
> (실제로 반영되지는 않는, 순수 미리보기).

### 자주 바뀌지 않는 내용(이름, 사진, 연락처, 소개 문단 등)을 고치고 싶을 때

이 부분은 시트가 아니라 `content.json`을 직접 고쳐야 한다. Claude에게 "이 문구를 이렇게 바꿔줘"라고
말하면 `content.json`의 해당 항목에 세 언어를 함께 채운 새 파일을 만들어 주므로, 그 파일을 GitHub에
올려 덮어쓰면 된다.

## 4. 방명록은 어떻게 작동하나

1. 방문자가 명함 하단 방명록에 메시지를 적고 전송하면, `index.html`이 Apps Script의 `/exec` 주소로
   내용을 보낸다(`doPost`).
2. Apps Script가 **박상태 교수 본인 권한으로 대신 실행**되어, 스프레드시트 1번째 시트에 시각·성함·
   이메일·메시지를 한 줄 추가한다.
3. 방문자는 로그인도, 가입도 필요 없다. 시트는 비공개로 유지된다.

## 5. 방문자 수는 어떻게 세나

- 같은 Apps Script의 `doGet`이 `오늘`과 `총` 두 숫자를 관리한다(스크립트 속성에 저장, 시트에는
  안 남음). 방문자의 브라우저에 "이미 셌음" 표시(localStorage)를 남겨, 같은 브라우저에서 다시
  방문해도 중복으로 세지 않는다.
- 매일 자정(한국 시간)이 지나면 "오늘" 숫자만 0부터 다시 시작하고, "총" 숫자는 계속 쌓인다.

## 6. 최초 설정 체크리스트 (이미 완료됨 — 재구축 시 참고용)

1. **GitHub Pages**: 저장소 Settings → Pages → Branch `main` / `/(root)` 로 배포 켜기
2. **Google Sheet**: 이름 "명함 방명록", 1행에 `시각 | 성함 | 이메일 | 메시지`
3. **Apps Script**: 그 시트의 확장 프로그램 → Apps Script에 아래 기능이 모두 들어 있어야 함
   - `doPost` — 방명록 접수
   - `doGet` — 방문자 수 조회(`?mode=read`/`hit`), 시트 내용 미리보기(`?mode=content`)
   - `setupSheets` — "이력활동"/"관심사" 탭 자동 생성 (최초 1회 실행)
   - `getDynamicContent_`, `autoTranslate_`, `yearKey_` — 시트 → JSON 변환 및 번역 캐시
   - `onOpen` — 시트 메뉴에 "📇 디지털 명함" 추가
   - `onEdit` — 한국어 칸 수정 시 번역 캐시 자동 무효화
   - `publishToCard`, `GITHUB_CFG_` — GitHub의 `content.json`을 직접 갱신(커밋)
4. **배포**: 배포 → 웹 앱, 실행 계정 "나", 액세스 권한 "모든 사용자" → 배포 후 나온 `/exec` 주소를
   `index.html`의 `id="gbForm"` 요소 `data-action` 값에 넣기
5. **GitHub 토큰**: GitHub에서 해당 저장소 하나만 접근 가능한 Fine-grained 토큰 발급
   (Contents: Read and write 권한만) → Apps Script 프로젝트 설정 → 스크립트 속성에
   이름 `GITHUB_TOKEN` 으로 저장 (코드에는 절대 직접 적지 않음)
6. **앱 아이콘**: `manifest.json` + 아이콘 5종을 저장소 최상위에 두고 `index.html` head에서 연결

## 7. 문제가 생겼을 때 확인하는 순서

- **방문자 수가 `NaN`으로 보임** → Apps Script의 `doGet`을 고친 뒤 **재배포**(배포 → 배포 관리 →
  연필 → 새 버전 → 배포)를 안 한 경우가 대부분. 코드 저장과 배포는 별개 동작이다.
- **"반영하기"를 눌렀는데 명함이 안 바뀜** → 스크립트 속성에 `GITHUB_TOKEN`이 있는지, 토큰 권한이
  해당 저장소의 Contents 쓰기로 되어 있는지, 토큰 만료 여부를 확인.
- **명함 자체가 안 열림(404)** → 저장소가 실수로 Private 으로 바뀌지 않았는지 확인(GitHub Pages는
  무료 계정에서 Public 저장소에서만 작동).
- **영어/일본어 번역이 이상함** → 해당 시트 셀(내용_영/내용_일 등)을 직접 고쳐 쓰면 그 값이 항상
  우선한다.
- **배포 주소(`/exec`)가 여러 개로 헷갈릴 때** → Apps Script 배포 관리에서 실제로 `index.html`의
  `data-action` 값과 URL이 정확히 일치하는 배포가 어느 것인지 먼저 확인.
